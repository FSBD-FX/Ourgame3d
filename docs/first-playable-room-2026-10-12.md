# 首个 2.5D 单人战斗房间

记录日期：2026-10-12，Asia/Shanghai。用户“开始制作”（EV-014）后的第一轮实现，工程为 `F:\Ourgame\UnrealGame\CodexDungeon.uproject`，地图 `/Game/Maps/FirstRoom`，UE 5.5.4。“烬堡”为开发暂名。

## 试玩

双击根目录 `开始试玩.cmd`，按 Enter 开始；Space 也可开始。WASD / 方向键在地面左右、前后移动，Space 跳跃，J / 鼠标左键攻击，E 拾取或进入出口，Q 切换已获得武器，R 重开。需要本机 `G:\UE_5.5`，当前使用引擎以 `-game` 运行，尚未交付独立打包版本。

清除房间内三个敌人后，右侧出口开放。靠近地面物品按 E 拾取；出口处有可拾取物时先拾取，再按 E 前进。前进会生成下一房，保留金币与已获得武器；死亡后按 R 从第一房重新开始。

## 本轮实现

角色以透明二维 PNG 动作帧绘制，房间由背景、地面与前景组成；按地面纵深排序人物，影子标出落脚点。地面 X/Y 与跳跃高度分开保存，跳跃不会改变地面纵深。攻击同时检验朝向、水平距离、地面纵深和高度差。

| 内容 | 当前原型规则 |
| --- | --- |
| 剑 | 伤害 26，范围 135，命中前摇 0.17 秒 |
| 斧 | 伤害 42，范围 150，命中前摇 0.31 秒；清房后掉落并可解锁 / 切换 |
| 敌人 | 第一房三个兽人，各 65 生命；追击、攻击、受击、死亡；后续房间生命按原型规则递增 |
| 金币 | 每次拾取增加 5 |
| 药水 | 恢复 30，最多至生命上限；满血不消耗 |
| 清房 / 出口 | 全部敌人死亡后开放右侧出口；附近拾取优先于出口交互 |

这些数值和小集合是本轮实现选择，未作为用户最终数值或内容数量。完整装备、背包、品质 / 词条、完整道具类别、随机地牢、Boss、成长 / 存档、手柄和合作尚未实现。

## 资产与成本

使用已保存的 Kenney Mini Dungeon CC0 模型和动作，通过本地 Blender 5.2.2 转绘。人类 / 兽人各有 idle、walk、attack、hurt、death，共 64 张 256×256 RGBA，统一落脚点 (128,220)；64 张已导入 UE。受击无原始 take，以待机姿势倾斜占位。当前房间、拾取物和攻击反馈为程序绘制原型，备好的五张道具图标尚未全部接入。中文 HUD 使用 OFL1.1 的 Noto Sans CJK SC。

本轮付费生成费用为 0；没有调用付费 API。转绘模型的二维画面用于验证规则，正式画风和动作质量仍待试玩确认。[原始来源与帧清单](../source-assets/prototype/first-room-v1/manifest.json)

## 事实、推理、风险

**事实**：已有可运行的小房间，基础单人战斗与掉落 / 清房循环有本轮构建和运行证据；长期完整系统尚未完成，原型美术也未获最终验收。

**推理**：先用这一切片确认空间、输入与攻击节奏，再在规则上扩展内容，避免大量制作动作和物品后再修改基础规则。

**风险与下一步**：不同武器目前复用基础角色攻击帧，装备换装尚无制作方案；正式动画、更多敌人与道具会增加持握点、遮挡、组合验证和数值工作。音频听感、发布打包、长时间运行与后续合作需分别验证。先依据试玩反馈调整可见比例与手感，再细化扩充清单。


## 开发实现边界

当前以 C++ Actor 保存地面 X/Y 和独立跳跃状态，再由 Canvas 绘制二维表现；这是可验证的表现与规则原型，尚未形成大型关卡的世界碰撞、通用物理或完整生产架构。后续按实测需要扩展 Paper2D / 图集、世界碰撞、材质、UMG、存档与合作同步，不能把当前二维画面视为这些系统均已完成。

`source-assets/prototype/first-room-v1` 作为已验证源版本保留。重新转绘应输出新的版本目录，并同步清单与导入记录，避免覆盖已有帧或混合新旧动作。
