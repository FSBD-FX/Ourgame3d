**事实**：已建立UE5.5.4工程，昨日的3D素材导入、待机和PIE验证通过；尚无可玩角色 / 战斗流程，也未建立二维角色动作图集。此前成功的是工具链和3D素材验证，不是最终2.5D美术。

本机Paper2D插件已存在于 `G:/UE_5.5/Engine/Plugins/2D/Paper2D/Paper2D.uplugin`，`EnabledByDefault=true`；昨日真实Editor日志 `UnrealGame/Saved/Bootstrap/editor-verification-20261010-101801.log` 已记录 `Mounting Engine plugin Paper2D`。项目没有显式插件条目或C++模块依赖，但不能因此说它尚未启用。Sprite / Flipbook导入、播放与本项目2.5D排序仍未实测。

**推理**：保留UE5工程、MCP、UI / 字体 / 音频及原始资产，只调整表现与玩法方向。下一阶段先用明确标记的二维占位验证空间和手感，再增加美术投入。UE的Paper2D Sprite / Flipbook可作为序列帧试验入口；Epic 5.5文档确认Flipbook以Sprite关键帧及持续帧数播放动画。[Epic Flipbook文档](https://dev.epicgames.com/documentation/en-us/unreal-engine/paper-2d-flipbooks-in-unreal-engine?application_version=5.5)

**风险**：固定相机不足以保证接近参考的视觉。二维角色动作缺口需要新绘制、合法免费素材或Blender转绘；3D模型转绘不会自动得到手绘质感。地面前后距离、跳跃高度和屏幕重叠若混用，会导致错误遮挡或隔着纵深命中。现成普通2D平台跳跃模板也不能直接代替可前后移动的清版动作。

## 空间与视觉规则

| 项目 | 下一阶段遵守的规则 |
| --- | --- |
| 镜头 | 固定侧向构图，玩家不自由旋转；房间内跟随范围和投影待实跑确认 |
| 地面移动 | 水平移动与地面前后纵深分开；原型先用平坦战斗区域 |
| 跳跃 | 高度独立于地面坐标，跳起仍能识别落脚点；影子留在对应地面位置 |
| 朝向 | 以左右战斗朝向为基线；前后移动不强制角色朝镜头或背向镜头 |
| 遮挡 | 根据地面位置处理角色 / 道具前后关系；跳跃不能仅因画面升高就错误改变地面先后 |
| 命中 | 结合攻击朝向、水平距离、纵深容差及高度规则；画面重叠不直接等于命中 |
| 场景 | 背景、可走地面和前景分层；地面边界清楚，前景不持续挡住战斗 |
| 表现 | 当前以二维角色和插画感分层场景为基线；3D验收角色只作测试或转绘来源 |

建议实现时分清地面坐标与离地高度，例如UE的X / Y对应地面、Z对应高度；具体镜头和Sprite朝向需一起验证。该约定是本项目建议，不是对原作坐标系统的断言。

## 第一个运行片段的验收目标

先做一个角色、一个敌人、一个战斗房间，按顺序验证：

1. 固定侧向画面中，角色可左右 / 前后移动，落脚点和地面边界可读。
2. 跳跃与地面纵深互不混淆，影子和遮挡正确。
3. 待机、移动、攻击、受击和死亡的二维表现可切换，左右朝向正确。
4. 同一纵深附近攻击能命中，超出纵深容差应落空；高度规则另有明确结果。
5. 敌人受击 / 死亡后掉落，清房后开放出口，形成最小单人循环。

阶段验收以真实可玩结果和归档运行证明为准。当前只是方向与验收目标已记录，上述玩法均未据此宣称完成。角色职业、武器总量、随机地牢、装备规模与合作网络不在这次方向调整中新增数量承诺。
