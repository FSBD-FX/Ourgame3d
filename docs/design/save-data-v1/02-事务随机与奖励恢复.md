# D-13：事务、随机与奖励恢复

日期：2026-10-14（Asia/Shanghai）；来源：EV-031“继续”。本稿为助手提案，状态是`design_only`、未实现、未试玩，不代表用户逐条批准。只补UE5＋Blender首版单人的持久化设计；IO、A/B两代、校验与发布marker统一见[保存规则](save-rules.json)。结构化操作表、去重键与20个恢复纸面案例见[transactions-and-rng.json](transactions-and-rng.json)。

事实：D-04要求地面移除、归属、数量、费用与最终属性同一事务；D-08要求原掉落、有限库存/次数、随机结果/游标与托盘固定；D-09已有跨账号与Run的样品购买、新局冻结/清待选项和原实付退款凭证；D-10已有事实/已读分离和结局receipt。旧文档均只承诺设计接口，没有实机持久化实现。D-07和D-06尚写“中途/Boss保存未采用”，本轮由精确完整tick续局方案明确覆盖这两项，旧源保留。

推理：一份较新账号余额与一份较旧Run可以各自校验成功，却一起复制样品或重复结局奖励。因此账号、至多一个未结束Run、完整模拟tick、日志、RNG与奖励证据必须作为同一个bundle选择。随机结果只保存seed不够：还要保留结果、游标、合格集合和原词条q，否则返回房间、改变背包或更新版本时仍可能换结果。

风险：本地保存无法承诺防修改或防玩家回滚自备旧档；崩溃只能恢复最后已发布完整代，不能保证零损。5活跃模拟秒是保存请求目标，磁盘失败、等待与尚未发布的候选会改变实际恢复点，不能宣传损失绝对≤5秒。强制提交会产生短暂技术暂停，历史日志/receipt会增加体积和写盘成本，目前没有实际耗时、体积或故障率数据。

## 1. 唯一成功点：完整generation发布

本tick先按原规则完成所有到期伤害与死亡、到期及破韧、存活者旧装备合法治疗，再到自动货币拾取和库存/设施提交。候选在这些原次序中构造，到完整tick边界才保存；不是先保存“准备买”，读档后再执行一次买。任何半次伤害批次、先扣钱未交物、先写账号未写Run都不能成为恢复点。

强制提交时冻结仿真和本局模拟时钟，等待完整bundle写入、校验并发布。发布前的结果属于私有候选；不把新词条、轮盘结果、成功状态或成功声交给玩家。发布后才确认这笔操作，相关消费者用OperationID/ReceiptID去重。IO期间不能继续跑world后再用旧候选覆盖。

写失败进入保存规则统一命名的`SAVE_FAILED_TECHNICAL_PAUSE`：保留同一CandidateID、post-damage基线、OperationID、抽样结果和游标变化，先检查marker是否其实已发布，再重试同候选。可取消的未发布手动操作只撤它的分支；HP、真实伤害、已走模拟时间、合法治疗以及同tick此前应处理的事件不撤。若同时有自动拾取/奖励，这些强制项仍需组成完整候选发布后才可解除暂停。取消不是加载上一次健康快照。

真实死亡、合法奖励/入账、已执行房间迁移和终局候选不能用取消复活或跳过保存。死亡候选失败时不得进入局外购买或开第二局。若进程崩溃，恢复只选最后完整已发布bundle；旧代可能回退战斗，但不得把未发布候选或另一代账号补进去。这个边界需在未来故障界面准确告知。

## 2. 两层去重：操作ID与玩法来源键

`ProfileID/OperationID`绑定完整规范请求和`request_digest`。请求包括操作类型、账号/Run、源/目的ID与必要版本、数量、原选择/落点、锁定报价/规则版本、券以及风险确认版本；不把重试计数、墙钟或展示语言混入。坐标/整数/字段顺序需要固定规范编码，不能直接对不稳定浮点或容器输出取摘要。

先查OperationID，再重验当前世界：同ID同请求返回原精确结果；同ID换商品、数量、目标或操作类型拒绝`OPERATION_ID_CONFLICT`。重复返回是查询原结果，不能把已消耗/丢弃/随Run结束的实例重新放进当前背包。失败/取消也保留该ID和请求结果；重新选择是新意图，而不是重写旧ID。

只查OperationID仍会漏掉“换新ID再领同一Boss”。因此还要查稳定来源键。核心键如下，完整字段表在JSON中：

| 来源 | 去重范围与键 | 保存的证据 |
|---|---|---|
| 有限敌真实死亡 | `RunID/RoomInstanceID/SlotID/SourceID/first_true_death` | 分配额度、死亡tick、固定结果与对象引用 |
| 整房来源 | `RunID/RoomInstanceID/SourceID` | presence含empty、完整结果及各index |
| 地面对象/拾取 | 固定地面ObjectID，另有`pickup_once` | 来源解析与真实入账两张关联receipt |
| Boss成功 | `RunID/RoomInstanceID/BossSpawnID` | D-06原成功事件，挂原奖励和D-10事实 |
| 首次Boss | `AccountID/BossID/first_boss_success` | 原首次SourceID、数量、首个合法成功事件 |
| 隐藏发现 | `AccountID/DiscoveryID` | 实际安全交互，不接受门票/到达替代 |
| 样品 | `AccountID/ContentUnlockID/sample_success_once` | 原Run/报价/实例/现金购买receipt |
| 天赋实付/退款 | `AccountID/PurchaseOperationID` | 原实付和唯一退款指针 |
| 结局 | `AccountID/RunID/EndingID` | 成功键、叙事语境、当时支线快照 |

同房同模板的不同敌人不能共用地面对象键：每敌来源实例必须纳入Slot身份。该细化不增加金币，也不改变D-08按整个有限manifest分配的预算。

## 3. 操作表

以下均为候选整代原子字段；细前置、是否可取消、恢复结果和来源引用在JSON的26项操作中定义。

| 操作 | 同时保存的最小效果 | 恢复边界 |
|---|---|---|
| 敌首次死亡、整房解析 | 真实死亡/终态、原分配、presence/完整结果、对象身份、游标 | 跨波/回调不再产出；empty也是已解析 |
| 地面金币/碎片拾取 | 对象移除＋钱包/永久账＋receipt | 未拾不入账；结算不再加一次 |
| 拾取/替换/丢弃/并拆栈 | 源目的数量、原/派生ID、旧物落地、最终属性 | 同实例弹匣/CD不刷新，HP只截新最终上限一次 |
| 商人库存解析 | 固定报价实例、初弹匣、完整附魔、价格、游标 | 发布后才能展示；看/取消/返回不刷新 |
| 已知商品、确定转轮整包 | 费用/合法券、整包归属、库存/次数 | 整包容量不够全部拒绝，确定转轮无新RNG |
| 有限轮盘 | 费用/券、次数、0..99结果、钱包或托盘、游标 | 满包不改池；待领托盘阻止下一转 |
| 钥匙箱开启、托盘领取 | 开箱扣钥匙/固定源托盘；另笔转同实例 | 开箱不自动入包，领取失败留原结果 |
| 锻造、附魔四操作 | 费用/券、原实例/版本、完整词条或整包去除、原q/游标 | 觉醒/重洗才抽；升阶保原q，洗净不挑坏词 |
| 隐藏入口权、房间迁移 | 门费/入场权、原目的room/seed、迁移状态、清理和一次跨章恢复 | 权不是发现；转换故障不二次扣费，load不再恢复20% |
| 非终局Boss/发现交互 | 原保证/首次奖励、账号标志、本局进度、剧情事实 | 同点伤害死亡先判；首次与发现各自去重 |
| 最终Boss终局 | 原12/首次2碎片、M05/解誓、结局receipt、Run结束/activeRun解除 | 先完整发布后结局页；终局金币0不改 |
| 死亡/放弃 | 原因/结算receipt、局内资产结束、已入账永久证据 | 不补地面未拾碎片，不给延迟命中新奖励 |
| 天赋购买/全退、研究 | 碎片、等级/永久研究、实付/退款receipt、版本 | 退款只原实付；研究/已购样品不退款 |
| 下一局样品待选、新局 | 账号待选转冻结快照/同笔清空、RunID/seed、固定起始配置 | 同启动重试同Run；继续不再20金币/满血 |
| 样品绑定/购买 | 首匹配N04原报价；购买时Run钱物＋账号永久资格 | 不转点、不FUN002、不设溢出托盘；死后资格不还 |
| 已读/跳过/回顾 | 仅展示标志/游标 | 不触发奖励、解誓、库存刷新或成功声 |

账号与Run的版本仅作单人本地完整性/串行写者约束，不冒充未来多人、云多端或服务器仲裁。未结束、暂停、starting、ending或recovery中的局均会锁住局外成长修改和新局创建。

## 4. 落地、领取和永久入账分开

普通敌人/清房来源先解析并固定奖励。地面落点暂时不合法时保存`RESOLVED_PENDING_GROUND`与原对象身份，后续投放只移动原引用，不再抽、不提前加钱。已落地未拾取是世界资产；玩家真实拾到后才原子移除地面物并加金币或永久碎片。

轮盘物品和钥匙箱结果在源端唯一托盘，领取需要原动作、安全与整物容量。托盘不是背包扩容，不自动使用，也不兑换金币。离区遗留确认或结束Run按D-08销毁局内未领物；不退已合法提交的费用、次数或钥匙。

Boss保证/首次碎片与发现首次碎片按原事件自动永久入账，与普通地面碎片不同；不再生成同奖可拾碎片。药物产出也不等于使用或实际治疗。结算显示已入账累计，不能把总产出、未拾地面物或未领托盘补成到账。

## 5. RNG与原结果一起保存

保留D-08五类流：路线、奖励来源、商店库存、附魔、轮盘操作。逻辑抽样身份与物理子流输入保存映射；在Profile/Run之下按room/来源实例/channel/ordinal分区。`SourceID`模板本身不是跨房唯一身份。

每流保存算法版本、seed或完整PRNG内部状态、下一抽样序数、底层原始数消耗数（含拒绝采样）和上次结果receipt。首次解析同时保存合格集合、presence（包括empty）、类别/模板/品阶、最终实例、完整附魔/原q。只存seed或只存游标均不够。

抽样在确认及前置重验后进入私有候选；费用、次数、结果和游标同代。商人库存、预定箱结果、路线/manifest可按原规则在展示/入房前预抽，但也要先发布才显示。未发布不能通过界面、动画、日志窗口或音效泄露结果；否则“取消无消耗”会成为免费预览。

每个来源实例、OfferID、箱ObjectID、轮盘useOrdinal、装备InstanceID/附魔revision/操作ordinal都锁定一次解析；换OperationID不改同源seed。附魔已发布后revision与原结果一起前进，旧revision请求拒绝；再次合法重洗须基于新revision并正常再付原费用。OperationID识别请求，不充当免费换随机种子的按钮。

v2的`integer_uniform_center_quantile_v1`不改：完整合法组合抽样、整数幅度和逐词原q分子/分母均存。升阶沿最初q映射，不能把新阶幅度反算成新q；词条/版本缺失进入恢复/迁移，不自动换词、重造或吞奖。

房间进入前固定有限SlotID、组、触发义务与奖励分配。还要存当前触发锁存、预留、预告/出现剩余时间、重试与每Slot终态，而非仅初始manifest。跨波、苏醒、实体化失败、深入线回退、读档和返回不重抽、不重新分预算。精确继续恢复原模拟tick；离线不走DoT/CD/预告，不因load运行一次生成回调。

## 6. 三项跨存续范围事务

样品购买必须一代包含：局内金币扣除、原ItemInstanceID交付/合法替换、原报价已售、账号对应研究样品已购和购买receipt。不能拿新账号资格配旧Run金币/物品。购买后死亡或丢弃仍算已购；未买结束保留资格，但下一局要明确重选，报价不自动续。

新局必须一代冻结天赋、解锁、所选样品、已购样品快照、规则版本和叙事语境，创建唯一RunID/seed/确定起始装备与20金币，同时清空账号待选样品。同启动OperationID重试恢复原RunID和原样品；账号待选清null不是“本局从未选”。继续原局不再次初始化。

终局必须一代入原12碎片/尚未领的首次2、设置M05和world_liberated、写本Run结局receipt及当时支线快照、仅首次为空时设置first receipt、结束本局并解除activeRun。首次receipt不能被之后回响远征的新支线重写。显示失败可恢复原文字，不能再发奖励；双死无新成功/结局。

天赋全退也依赖永久凭证：每个当前等级须恰有一张未退款receipt，退原`actual_paid_shards`，逐张标记这次重置ID。原实付2＋6、余额5全退为13；重复不再退8。再买付2形成新receipt，下次只退新2。缺凭据则整体阻断恢复，不按当前价格补造；研究和样品永久记录不受重置影响。

## 7. 恢复与日志压缩

load只装载选中完整bundle的状态与证据，不把Operation日志当命令自动重放。最新已发布代损坏、未知版本或marker不可信时按root规则进入恢复说明，不自动降到较旧兼容代；只有明确选择的整代备份恢复才能回退。旧实例引用是历史receipt，不是发物指令；旧Boss成功记录不是再次发奖接口；已读剧情不是成功证据。未完成动作恢复原进度，后续只有正常新模拟tick才能推进，不在加载函数免费完成。

日志可无损压缩、共享重复结构、重建索引；已结束Run可移除战斗位置/弹体等非永久恢复载荷。每个完整bundle仍须带OperationID→规范请求/digest/原精确结果、永久碎片与首次/样品/结局证据、天赋原实付和退款指针、已结束Run tombstone。不能把唯一证据放在另一代或可丢外部日志，也不能只留最近N条、余额/等级、counter或有误判的Bloom filter。

无管理迁移时应满足：`earned_shards_total = 当前永久碎片 + 尚未退款天赋实付之和 + 永久研究实付之和`。退款不是新earned；掉地未拾也不是earned。压缩写失败继续选旧完整代，成功的新压缩代必须在以上证据和精确重试结果上等价。

本地音频与磁盘marker无法物理原子：同进程只为新发布边沿播一次，重复操作/load不补播成功声；崩溃可能漏掉一次声效。静态结果与待读剧情可恢复，不能为了补声重播交易。当前不声称跨进程严格恰好听到一次。

## 8. 纸面恢复案例与未来验证

JSON列20例：同点致死前不拾碎片、已拾丢回复、敌死无落点、empty来源、轮盘未发布失败、满包箱托盘、样品跨域写坏、买后死亡、重复退款、新局待选清空、Boss双死、终局展示前退出、死亡写失败、波次/DoT离线续局、门票后转换故障、改请求复用ID、压缩失败、手动取消保真实伤害/其他强制项、放弃未拾奖和5秒请求未发布。

这些是待实现断言和一致性推演，不能记成真实崩溃测试。未来须对每操作在候选前、写入中、marker前后及回复前注入故障，确认恢复只出现完整旧代/新代；实测流状态、随机不可提前看、样品/结局/退款与压缩去重，并量测实际存档体积、延迟和技术暂停感受。只有运行中的UE5结果和故障证据能证明实现完成。
