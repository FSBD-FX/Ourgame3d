# 版本兼容与后续合作边界

日期：2026-10-14，Asia/Shanghai。来源事件：EV-031“继续”。状态：**助手设计提案，未逐条验收，未实现存档或联网，未运行引擎验证**。本稿沿已确认的 UE5 + Blender、二维角色与分层场景的 2.5D、首版单人方向；JSON 契约见 [compatibility-and-coop.json](compatibility-and-coop.json)，整根保存与 A/B 发布规则以 [save-rules.json](save-rules.json) 为准。

## 事实、推理与风险

**事实**：D09 要求新局冻结天赋、研究、样品资格和规则版本；暂停待续仍是未结束局，不能购买、全退、选下一局样品或开始第二局。D10 把账号事实、本局成功和文本已读分开。D11 的暂停冻结同一模拟时钟，恢复输入必须先释放/回中再重新确认。D12 正式坐标是正 Y 远离镜头并投影向上，绘制按负 groundY 排序，跳跃不改地面排序。

本轮只读检查 `UnrealGame/Source` 与 `Config`，未找到正式 Profile/Run 存取入口。实际 C++ 的 `StartPlay` 调 `RestartRun`，把金币设为 0、武器设为原型 sword、房号设为 1；`DungeonProbe::SaveReport` 写出的 `runtime-report.json` 是运行证明报告。它没有完整账号、Run、动作、随机状态或所有权记录，不能作为续局存档。这个结论限定在已检索的 C++/Config，**没有声称检查过所有二进制资产或本轮实机运行**。

旧 HUD 中 `Ground` 为 `v=510+Y×0.48`，角色按 groundY 升序绘制；旧输入 W/Up 产生负 Y。正式 D11/D12 是 W/Up 产生正 Y、远处向上、负 groundY 排序。源码尚未改动，也没有证据证明存在可导入的旧正式存档。

**推理**：D13 采用精确中途保存和恢复，包含 Boss 战。它明确覆盖 D07 `/persistence/midcombat_save_adopted=false` 与 D06 `/persistence/save_during_boss_fight_adopted=false` 两个当时尚未采用的占位决定；历史原稿保留。继续局保持原 RunID、当前动作/弹道/状态/随机结果，不能退到房间入口、取消攻击、满血、清 DoT 或重领奖励。

迁移、保存和恢复均以**同一 ProfileID、同一 GenerationID 的完整 bundle**为单位：账号、至多一个 activeRun、设置、已读和操作凭据必须一起。研究样品的局内扣款、实例交付、offer 已售与账号已买标志不能拆成不同代。5 秒只是活跃模拟秒的自动保存请求目标，不能宣传为断电最多损失 5 秒。

**风险**：没有已证实的旧正式格式，不能许诺把现有原型进度迁入。精确继续需要旧规则可执行，不是仅保留一个版本字符串；保留旧目录、状态解释和回归样本有包体及维护成本。损坏、未知版本、缺付款凭据不能用清空、当前价或较低兼容代补猜。合作尚未决定人数、网络拓扑和平台；本稿预留身份与接口，不能据此宣称合作规则、成本或工期已经确定。

## 三种版本分开记录

| 字段 | 描述什么 | 不能据此推断 |
| --- | --- | --- |
| schema_version | 存储字段、类型及结构 | 新结构天然兼容旧规则 |
| content_rules_version | 内容与价格、动作、状态、掉落、房间规则的精确清单和 digest | 新局天赋或新版数值可套入旧攻击/旧遭遇 |
| coordinate_version | 存储世界轴、单位、原点、房间局部坐标及向量的解释 | 显示方向变了就应把已存 Y 全部取反 |
| build_id | 构建诊断身份 | 上述三类版本已经兼容 |

设计 JSON 顶层的 `schema_version:1.0` 仅是设计文档格式，不是已经落地的产品存档版本。本稿不虚构原型存档版本号，也不登记没有真实输入样本的通用“旧版导入器”。

每条迁移必须登记明确的来源三元组、目标三元组、MigrationID、变换版本、完整 ID 映射及前后不变量。未知版本没有默认兼容路径；降级也没有默认路径。已知 ID 更名只有在语义和所有引用一并保留并验证时，才可成为明确迁移。

## 迁移只复制到新代

1. 获取该 Profile 的唯一写入权，清点 A/B bundle、commit marker 和迁移档案，先识别最高可信的已发布代。
2. 校验准确字节、ProfileID、GenerationID、父代和版本。将原 bundle、可用 marker、哈希和诊断复制到独立迁移档案，滚动 A/B 不能替代原件留存。
3. 查已登记的兼容路径及旧规则清单。缺可执行规则、未知引用或无路径时进入 RECOVERY_REQUIRED，保持原件。
4. 在候选完整 bundle 上转换；保留 RunID、冻结成长/叙事快照、事件与账本身份、模拟时间，不运行新局/BeginPlay 奖励初始化。
5. 验证全部引用、库存/地面/托盘/消耗态唯一归属、账号与 Run 关联、收支、凭据、随机结果、动作/刷怪游标、故事域和设置。
6. 判定空间变化是否只是显示适配；真实世界基变化才做完整坐标变换并复验边界与命中。
7. 用同一个合法源样本验证迁移前后的下一事件、费用、状态期限、命中与随机结果一致；暂停和离线不能推进。
8. 恢复/迁移界面显示来源、目标、原 RunID 和保留结果；如果选择旧备份，先显示明确损失。取消仍保持旧权威原件。
9. 只调用根保存规则的 COMMIT-01～07，发布一个新代，记录来源哈希、版本、MigrationID 及结果；没有第二套迁移发布算法。
10. 确认丢失后的重试先查提交记录；同 MigrationID 和摘要返回同结果，不再次转换、发奖或消耗样品。原件不会因迁移成功而自动删除。

活跃局的无损**结构表示**升级可以保持同一 RunID 和旧规则语义；不能静默把 `content_rules_version` 换成当前规则、重新算当前价或重建房间。新规则供之后的真正新局选择，必须先有可信结束事务并通过 D09 HUB_IDLE/无未结束局检查。旧规则无法执行就阻止继续，不用“技术修复”取消危险动作。

## 损坏与未知版本不能悄悄退回

已知未发布的临时文件与最新已发布损坏是两种情况。前者按根 IO 契约隔离，不能因 JSON 完整就提升为已提交；后者只要最高可信 marker 指向的 bundle 坏了，先进入 RECOVERY_REQUIRED，不能自动载入较低完整代并继续写，掩盖新进度丢失。

最高已发布代是未知新 schema 时，也不能跳过它选较低“本机能读”的代。保持原件只读，等待兼容构建或已验证迁移。marker 本身未知/损坏导致无法证明最高代、同代不同 digest 或身份冲突时，保留相关原件并请求明确恢复。

可选备份必须是经验证的**完整同代 bundle**，不是拿新账号余额配旧世界。界面列出备份记录的模拟时间、房间以及可能失去的碎片、研究/天赋、样品标志、故事事实和设置。用户确认后按根规则发布带 restored_from 审计的新代；不会用损坏较新代推测“补领奖励”。没有可用局时，仍保留未结束锁；只有明确结束不可恢复局并形成终止记录，才可释放锁，且不新增奖励。账号也无法验证时不猜余额、不归零覆盖；另建 Profile 必须保留旧文件。

## 收支、成长、剧情与输入不改语义

- D09 每个已持有天赋等级都须恰有一份未退款的实付凭据。退款用原实付，不能用新价格、旧总价上限或估算值；研究不退。守恒为：可信累计获得碎片＝当前余额＋未退天赋实付＋研究实付。
- 同 RunID 的成长/研究/样品/叙事快照不变。暂停、主菜单、迁移、恢复中都不能绕过未结束局锁。
- 保留负词及其原始资格、当前 HP/专注/弹药、状态 next_tick、CD、治疗预算、攻击已发/已命中记录、活投射物、刷怪锁存/预留和 RNG。非法或缺失数据进入恢复，不以删除负词、净化状态、补满资源使其“合法”。
- 历史奖励消费与事务凭据一同保存。迁移不补发从对白、位置或物品猜出的奖励，也不自动领取历史未领取物。
- 只有可信旧 Boss/发现成功证据可映射 D10 账号事实；不得再次付钱/碎片，不得把新 Run 节点标成已过。可信终 Boss 成功须让 STORY-M05 与 world_liberated 一致；没有首结局凭据/当时支线快照就保持未知，不能拼造历史插页。
- 文本已读不证明故事事实；故事事实不证明当前局通关；教程已看不证明动作完成。跳过/回顾/恢复待播提示不发游戏奖励。
- D11 设置重绑迁移必须检查所有上下文冲突、必要操作和退出路径。已知映射不兼容时提出明确修正预览，经确认再发布完整新 bundle；不能静默覆盖原映射，也不能借重置设置接受未知 schema。
- 恢复先在暂停中构建完整世界，清掉物理按键/摇杆状态和未接受的输入缓存，释放/回中后重新确认。已接受动作和费用按原游标续行；不把暂停前按住的确认变成跳跃、攻击或付款。
- UTC/墙钟只作审计。离线和迁移耗时不治疗、不回专注、不清状态、不充 CD、不刷怪。

## 坐标迁移先判断世界语义

**只有输入/投影/绘制顺序改变**，而已存世界轴、单位及房间语义相同：位置与向量用恒等变换。一次联调 D11 输入、D12 投影、负 groundY 排序、地面影子、攻击/出生预告和目标提示。必须验证同一世界点对的距离、命中、碰撞、可达性不变；正 Y 投影向上、远者先绘，跳高不改变排序。旧画面 +Y 朝下不构成“存储 Y 应取反”的证据。

**真实存储世界基改变**：需明确可逆的旧→新变换，区分点与方向、单位、原点及每个房间的局部/世界空间，同时转换：

- 玩家/敌人/可交互物的地面位置，独立高度，以及适用的速度、加速度、朝向和瞄准向量。
- 锁线攻击的原点、方向、端点、扫掠/判定几何，活弹中心、前次扫掠位置、速度和追踪目标。
- 陷阱、召唤物、AOE、落物点、领奖托盘及归属空间。
- 房间局部/世界变换、入口/出口、出生和备用锚点、可达路径、触发区域与连续深入深度的基准。
- 镜头地面锚点、目标提示、地面影子和预告几何的引用。

随后复验 D04 距离/LOS/掉落与出口许可、D05/D06 身体/受击体/中心精检与扫掠、D07 边界/出生距离/路线/重叠。混合坐标、超界或无法证明语义保留即拒绝发布。正常载入不自动安全传送、取消攻击、清 DoT 或复活槽位；D07 明确技术修复是另一项有记录的操作。

## 后续合作只预留接口

现阶段仍只有一个本地玩家、一个本地判定权威。键鼠与分配的一个手柄合并成一个意图流；设备不是第二名玩家。D11 暂停完整冻结单人时钟，D04 拾取/替换事务与唯一归属保持，D08 局内金币、D09 账号碎片及未结束局锁保持。

| 预留概念 | 作用 | 当前单人约束 |
| --- | --- | --- |
| ParticipantID | Run 范围内稳定参与者身份，避免以手柄序号、Actor 指针或显示名当永久身份 | 仅关联当前玩家，不生成客人/第二槽或客人成长 |
| AuthorityID | 有权接受意图并提交结果的判定者身份 | 只有本地 resolver；不代表选了主机/专服/权威转移 |
| OwnerScope | 为账号永久数据、Run 钱包、玩家库存、世界来源明确归属范围与 ID | 每实例一个合法所有者；不新建共享钱包或交易 |
| RequestID / OperationID / EventID | 请求摘要、提交凭据、唯一奖励/子命中事件相互关联 | 同请求重试同结果，不同摘要拒绝；不因此指定网络协议 |

输入链为：物理设备 → D11 上下文消费后的意图 → 权威规则验证 → 已提交结果 → 表现。意图可预留 RunID、ParticipantID、RequestID、意图类型、稳定目标 ID 和适用的来源/目的地/报价版本；**不能直接设置 HP、金币、持有实例、命中成功、奖励或随机结果**。当前所有距离、LOS、安全、规则、报价和库存检查仍由本地权威处理。

本地精确中途快照不是联机快照语义。不据此增加共享钱包、均分掉落、复活/倒地、友伤变化、暂停投票、客人成长、后加入、云同步或平台账号。稳定 ID/hash 也不是远端认证。现有加载器以后遇到未知参与拓扑应拒绝，不能猜成单人。
