# D-13 保存字段与局内继续设计 v1

日期：2026-10-14（Asia/Shanghai）
触发事件：EV-031，用户“继续”。状态：`design_only`；`runtime_implemented=false`；以下新增保存方案均为助手提案，未逐条批准、未制作、未实机验证。

## 事实、推理、风险

**事实。** D02/D03以活动局仿真秒计动作、DoT、CD，D04暂停冻结同钟并清输入缓冲；D05普通敌死亡不销毁已发弹的容量，D06成功结算必须先做同点全量伤害/死亡；D07有限未来槽、整组预留、深入锁存与预告时序跨波保持。D09已要求未结束局锁天赋/研究/全退/样品选择/新局，并冻结起局成长；D10事实与已读独立；D12要求动作绝对时间驱动表现。旧D06/D07的战中保存false是当时尚待D13决定的接口状态。

**推理。** 只存房号、玩家血量、种子不能准确继续：这会漏掉旧弹、下次燃烧跳点、已发/未发子段、预留、首次奖励与实付票据。此版采用同本地ProfileID的完整一致bundle，允许暂停退出与精确战斗继续；D13显式覆盖旧D06 `/persistence/save_during_boss_fight_adopted=false`、D07 `/persistence/midcombat_save_adopted=false`，旧文件保持只读。继续仍是同一个RunID。

**风险。** 这是保存所需事实清单，不是已有存档格式或运行保证。代价是完整快照较大、恢复校验和版本迁移复杂，必须覆盖实体、事件和跨账号Run交易。尚无运行数据，不能许诺写入耗时、档案体积、掉电安全或可读写成功率。文件替换、持久化屏障、代际回退、写失败和迁移策略统一以[save-rules.json](save-rules.json)为准；此文不另建一套IO流程。

## 根数据域

根头部沿根方案保留 `ProfileID`、`GenerationID`、`parent_generation`、`schema_version`、`content_rules_version`、`coordinate_version`、`build_id`、`run_sim_time_or_null` 和完整 `payload`。其中ProfileID只表示本地档身份，不能当作未来联网账号认证。一个本地档至多有一个未结束activeRun；账号、activeRun或null、设置/已读和统一日志属于同一代，不从两个完整代中各挑“最新”金币和样品旗标。

三个版本各司其职：schema描述布局/编码，content_rules描述具体内容/数值/算法，coordinate描述持久化世界位置、向量、坐标空间和房间基准解释；输入、投影、排序适配要联调，但属于表现/构建规则，渲染变化本身不推出世界轴变化。D12登记旧原型正Y屏幕向下与正式投影向上的差异，若世界坐标语义未变，登记恒等世界变换并适配表现即可；不可因此擅自翻旧Y。只有真实世界坐标解释变化才做完整实体/向量/弹线/锁点/锚点映射。三版本合同以[兼容设计](compatibility-and-coop.json)为准；所有迁移保原档。

`account.active_run_id` 与 `activeRun.RunID` 同时存在且相等，或同时不存在。`RUN_STARTING`、`RUN_ACTIVE`、`RUN_SUSPENDED`、`RUN_ENDING`、`RECOVERY_REQUIRED`都保持未结束局锁。回主菜单/营地剧情不会解除锁。只有原结束事务成功完成才可恢复HUB_IDLE；暂停局显式放弃沿同一结束事务，不给额外Boss/房清/过门奖励。

## 冻结点与恢复顺序

保存边界是完整仿真tick/事件批次结算完成后；本设计不为UE新定固定tickrate。已到同点的伤害/死亡、合法治疗、自动拾取、真实动作提交和触发/接纳/房清各按原模块顺序走完，才能捕获。不能把“Boss先死但同点致死旧弹尚未结算”的半状态存成成功。纯输入请求和未确认整理意图不属于已接受动作。

权威 `run_sim_time` 保存double往返精度，所有位置、速度、锁定时间采用相同精度要求。墙钟仅供显示/诊断；关机后没有离线恢复、DoT补跳、HoT、聚焦、CD、苏醒、刷怪或音乐进度。动作保存原accepted_start、冻结完整时间轴、锁点/锁定快照、已消费子事件和剩余schedule；每个未来事件保EventID、绝对due_time、remaining_s及原顺序。`next_tick`和绝对deadline保原数值，禁止从“当前墙钟+剩余秒”重新排。冗余时间的数值校验和编码依根时间合同。

恢复步骤：

1. 校验完整同代bundle身份、内容与坐标版本及根完整性；有异常走根恢复流程。
2. 在禁活动、禁输入的暂存世界载入账号、全部既有房间、实例、归属、Actor/旧弹、未来义务、预留、RNG、事务和已读，再交叉校验。
3. 重建原动作姿态、原锚点提示、投射物和剩余预告。场景可渲染但仿真仍暂停，未消费的未来事件不提前运行。
4. 玩家新按明确继续，确认键由UI消费；世界按钮全部松开、轴回中后才启同一仿真钟。断连重连/焦点恢复也不自动启钟。
5. 原动作、CD、状态、敌人、预告和世界效果沿原剩余时序继续；不治疗、不补弹、不清场、不赠无敌、不重开动作。

起局初始化只属于新RunID的一次原事务：WPN-SWD-001、grade0、无附魔与20金币。继续不执行该初始化；同OperationID的新局重试恢复原RunID及原成长快照，不因账号下一局样品选择已清null而覆盖本局冻结选择。

## 必须保留的细节

**装备与归属。** `content_id`是模板，`instance_id`是唯一装备，`instance_version`是并发版本；不能混用。v2的enchant_package、enchant_tier、affix_ids、magnitudes、original_quantile_rationals、generation_seed、algorithm_version、affix_catalog_version、attribute_rules_version、weapon_skill_cooldown_deadline分别保原值，再加D08 grade与magazine_remaining。原q不能由magnitude倒猜，未知词条不静默剥除。每件装备/每个StackID恰有一个合法槽位、地面或来源托盘归属；全栈移保ID、拆分/合并保既成结果。角色共享CD不随实例移动清空。

**锁定快照。** 起攻固定动作时长/速度，玩家40%锁定伤害、资源、暴击和资格，敌人/Boss按原50%锁线；这些已经接受的结果是事实，必须保存。它们与“保存当前最终属性作为常驻缓存”不同。当前有效属性仍从同规则版本的装备、冻结天赋、遗物和状态来源派生，载入不能像新换装再截一次HP。攻击/弹体保旧锁定grade和附魔，不能被载入时的新显示覆盖。

**状态与实际预算。** burn等强刷新保原next_tick，regen_hp保已跳次数与下一跳，temporary_tonic正负同包。shock是瞬时追加削韧，不能载入再冲击一次，只保存已消费事件和target ICD。吸血保每AttackID实耗3HP预算，还要保角色滚动1秒每次实际治疗的仿真时间/数额，才能知道6HP窗口何时真正释放；仅存“剩0HP”不足。ITM-PAS-008保本房效率后实际治疗6HP预算、8秒CD及真实死亡去重，换装/波清/回房不重置。

**死者旧弹。** 普通敌死可以留已发弹，仍占live容量。保存原owner的最小tombstone：身份/阵营/死亡消费事实/攻击归属，只服务尚存攻击/状态引用，不重建可行动AI、身体或第二份奖励。最后引用释放后才可清除。已接受但未发射的整组容量与已发live容量分别保存，死亡/打断只释放原规则许可的未发部分。

**未来槽与真实休眠。** planned/queued/reserved/warning槽是有限义务，没有HP/身体；真实dormant/emerging是可受伤实体。保存每个SlotID、GroupID、依赖、TriggerID锁存、连续地面最大X/深度和整组角色帽预留。保存reserved_since、原候选/锚点、重试计数、backoff、预告余时、显现/唤醒/喘息/全房间隔，不把继续当作新入房。预告半播后只剩原余时；到物化时仍按D07复核，真实失败才保同ID重做完整预告。不能借反复退出把12秒故障等待归零。

**Boss与结局。** phase ID保原类型：部分Boss用整数，部分用稳定字符串，不能统一parse成另一个值。pending只取latest，原mandatory recovery与cue_deadline不重开。合法成功前旧弹仍可造成同点死亡，玩家同死没有新Boss奖励/剧情/ending；合法成功提交后才按D06清Boss自有世界伤害。玩家已经附着的DoT/next_tick/CD仍保。结局以本Run BOS-DEM-001合法成功为证据，END-OPEN-GATE凭据保原支线插页快照，未看演出仅补展示。已读不等成功，账号M05不自动完成新回响局。

**来源、托盘与样品。** 普通金币死亡只生成地面，真正存活拾取才入钱包；奖励来源解析和拾取两份消费事实分开。bonus_presence为空也是已经解析结果，不重抽。轮盘未知物品和公共箱结果属于来源唯一托盘，满库存不能送额外背包或地面副本，钥匙/次数/费用不因未领取退款。门票入场权保RunID/HiddenNodeID原票据，支付不是发现或Boss奖励。D09样品保first_qualifying_N04绑定、OfferID/ItemInstanceID与现金价；永久样品旗标、扣金币、交付/旧物落地、已售和两域版本同bundle，不从不同代拼接。

**故障修复边界。** 普通continue从不取消动作/清弹/重定位。仅玩家明确进入D07技术修复，才能按[根修复合同](save-rules.json)取消未发动作和room绑定live攻击且不退款，尚未完成活体合法重定位并给完整预告；HP、库存/币、状态next_tick/期限、CD、预留、锁存、完成真死槽/奖励保留。不能复活完成Slot；没有明确可恢复姿态政策就进入恢复，不能偷偷idle。

## 不单独持久化的缓存

- 当前derived最终属性、品质显示名、面板比较值/总分，均从同版本原事实派生。D09逐来源talent_contributions冻结快照按原规则保留并核对，但不是当前最终属性。

- 按键按住状态、轴输入、primary/item缓冲、输入事件队列、未执行整理意图和纯交易/风险预览。
- 可派生HUD清波/房清/完整安全标签、最终容量合计；真实槽义务/预留/事件记录仍是权威，派生值必须核对。
