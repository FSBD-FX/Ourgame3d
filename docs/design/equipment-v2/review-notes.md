# 属性与附魔设计v2审阅记录

2026-10-12。本轮交付是设计文档和结构化目录。用户要求：属性、全装备可用的分级附魔、各级上限及好坏结果。I–V五级、22项可修正属性、36种词条、概率和金币费用为助手原创方案，等待制作与试玩调整。

## 已完成的交叉审阅

词条、属性计算、生成工坊三部分由不同分工编写，互相检查其他部分及共同规则；根代理整合并执行导出校验。不是游戏运行审查。

| 发现 | 最终处理 |
| --- | --- |
| 阶级标签数组与导出脚本整数预期不同 | JSON保留tier与label；脚本提取tier校验，已实际执行通过。 |
| 词条好坏枚举、元素机器键不一致 | 统一beneficial/harmful及burn_dps/slow_pct/shock_flat；好坏与数值符号分别存储。 |
| 逐次重算百分位会使升阶结果漂移 | 初次无偏整数抽样后保存桶中心有理q；连续升级始终读取原q。负词也升幅，无合法区间提前拒绝。 |
| 负护甲/魔抗/韧性可能扣出下界，或变成无效果坏词 | 按物品基础保护/固有韧性加成求合法幅度交集，不借玩家基础韧性填补。负reach与专注成本也先校验有效范围。 |
| 穿脱HP上限可能凭空治疗，0.4HP被抬到1 | 内部仅min(oldHP,newMax)；HUD显示取整不能回写。死亡保持0。 |
| 旧弹命中期间换装，可能追改攻击或保留旧治疗效率 | 攻击伤害/暴击/吸血率用锁定点快照；目标保护与受治疗者效率用结算当时属性。 |
| 玩家死亡后，延迟吸血可能回复到正HP | 所有治疗先校验存活；死亡回复0，不消费治疗预算。 |
| 首目标受保护、已有强状态或被击杀，元素机会可能转给后排 | 首次正数直伤确定唯一目标；就绪角色CD先消费再尝试，拒绝不退，尸体不挂状态，也不改找下个目标。 |
| 升阶只检查上限会漏过区间重叠 | 同时校验逐级下限、固定档、幅度整数与单调映射。 |

## 实际验证范围

运行本目录`build_design_catalog.py`，报告见[validation-report.json](validation-report.json)：

- 33武器、12防具、22属性、36词条、180档范围与单位/适配/互斥检查。
- 45件×五级=225种装备等级组合，三种方案资格共675单元；穷举合法正负组合，不用概率降级填空。
- 将当前合法整数幅度的原q映射到后续连续合法等级，验证范围与幅度不减；空区间按拒绝处理。
- 33把武器×（12套防具+无甲）=429组II级示例的公式、有限数值和最终边界。
- CSV回读与JSON对应；逐件记录v1基础定义及源文件SHA256；文档本地链接检查。

这些不是UE游戏测试、掉落统计、经济模拟或存档故障注入。工作表的例子不是固定掉落、最优搭配或推荐最终数值。

## 制作后的验收与缺口

先接通实例状态、属性重算和面板，再做附魔生成/战斗触发与工坊事务。需从运行中的游戏检查备用槽休眠、同攻击暴击、多段与穿透快照、群攻元素限额、负面反馈、吸血预算、换装资源、重复确认与读档恢复。动作速度封顶在纸面上保留家族节奏差异，力量感与刺击感仍须实际动画、声音和试玩验证。

概率与价格尚无完整一局奖励依据；后续敌人/道具/关卡设计完成后再验证收益与代价。完整附魔玩法、工坊界面、存档与合作均未实现。本轮未改玩法源码，未付费生成资产。
