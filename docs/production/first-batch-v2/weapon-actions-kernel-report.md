## 接口合同

实现：[DungeonWeaponActions.h](F:/Ourgame/UnrealGame/Source/CodexDungeon/DungeonWeaponActions.h)，命名空间`DungeonWeaponActions`。

- `FWeaponActionsKernel(Weapon, InstanceId, Ammo, Focus)`由调用者提供真实初始资源；备用武器用`RegisterWeapon`显式登记。同实例不能重复登记；不同实例各有弹匣/技能CD，Focus仅角色一份。
- `StepTo(Now, FContext)`是唯一推进模拟钟的路径，返回并清空待交付事件。Now必须有限且不倒退。Context在该区间恒定，属性、甲的恢复条件、落地/发射枪口等外部事实变化时必须拆步。低帧大步返回所有真正到期子事件一次，重走同一时刻不补发。
- `TryStart(Primary/Skill, Now, Context, FreshPress)`要求与已推进的当前时刻相同，外部共同动作门`CanStart`合法。Primary仅弩/杖；近战三段普通攻击继续由旧核负责。技能只地面且不能插入普通攻击后摇。
- 起攻冻结整套时间/速度；40%锁点重验整轮成本并冻结伤害/削韧/射程/成本/技能CD/外部已解析的一次暴击结果。预算不足发`LockFailed`，不预留、发射、扣费或启CD；不返空攻名额。锁成功仅增加reserved，实际`ProjectileEmitted`或`ActiveWindow`才扣真实资源。
- `FContext.FocusRegen/FocusDelay`传入当前甲及有效属性算出的实际恢复率/等待时间，积分至当前模拟钟、封顶100；只有真实Focus消耗更新`LastActualSpend`。预留、释放、切换和暂停不重置该时刻。现有Fighter.Focus/恢复计时未来必须移除独立权威，仅镜像此Budget；绝不能两边同时扣费/恢复。
- `PressReload`支持完整手动装填/再次T取消；取消丢进度、不回弹，同一时刻禁止攻击；末弹仅在完整后摇结束后触发自动装填，空中延后至合法落地。取消后不会立即自动重装。装填速度在开始时冻结。
- `TryReverseCancel`仅普通攻击前40%反向；技能没有新加的反向取消权。`Interrupt`接收外部已判定的真实破韧/死亡等理由；普通未破韧伤害不应调用它。取消释放未发预留，已实际消费不退、旧发射receipt不撤、已锁技能CD不刷新。
- `EquipCompleted`只提交外部已真正完成的0.35s切换/装备动作；不自行执行Q动作，不重置实例弹匣/CD、Focus或空攻。其他UI输入优先级与交易/拾取依旧由外层负责。
- `NotifyTakeoff/NotifyLand`只由真实起落通知。共享Budget是**单角色空攻权威**。近战适配器须先查`CanAdmitExternalMeleePrimary`，在旧近战核确实接纳起攻后同一原子批次调用`RecordAcceptedExternalMeleePrimary`。旧核的Grounded/AirPrimarySpent只能镜像/进一步拒绝，不能独立授予新名额；失败起招不能先消耗名额。新技能与切换不重置名额。共同排他动作门也必须覆盖两核。
- `Capture/Restore`保绝对时间、原锁点、reserved/实际支出时刻、实例弹匣/CD、发射receipt、子段及事件游标。Restore先完整验证后替换，未知版本/NaN/不一致快照拒绝且不改活状态。未接纳的输入缓冲私有且不存档，恢复/暂停用`ClearPendingInput`清除；已接纳但未交付事件保留一次。只有未来子事件继续执行，不推进离线时间。

### 新接口及调用顺序

```cpp
// 必须先以真实当前甲/属性/区间上下文StepTo同一Now；事件先交世界适配器。
auto Events = Kernel.StepTo(Now, Context);
bool Spent = Kernel.TrySpendExternalFocus(Now, Amount, PersistentExternalReceiptId);
double ActuallyRestored = Kernel.RestoreExternalFocus(Now, Amount, AnotherPersistentExternalReceiptId);
```

- Spend/restore只接受有限、正数、有实际可表示数值变化的Amount、非0新ReceiptId、活角色、Now==核当前clock。不会暗中推进钟/积分恢复，不要求新的动作、不会清已有动作或空攻budget。
- Spend仅可用 `Focus-ReservedFocus`；失败不改Focus、reservation、LastActualSpend、任何ID/账。成功更新实际Focus及最后消耗；在锁前真实外部消耗可令之后武器锁失败，该消费不会退款。
- Restore返回实际增加量，含封顶100后的量；不释放reservation、不更新HasActualSpend/LastActualSpend；满额或精度没有实际增加返回0且不占receipt。正常失败可用相同ID修正后重试。
- 外部ReceiptId为**每角色、跨spend/restore共用的持久唯一域**，成功后再用同ID均拒绝，不再消费/退款。内部发射的Issued.EventId为另一个明确域，整数偶然相同不冲突。返回值是此次是否产生新效果，不会把重复成功重新报告为再次恢复。
- 调用者必须保存其ID分配进度/事务事实并与本核同代保存；不能重启就重用本角色已经成功的ID。核账存防重事实，但不代替物品数量/费用事务、来源归属、D13完整IO。
- 原Fighter.Focus及FocusConsumeAge必须改为镜像，SpendFocus封装本API；恢复只在StepTo积分或明确外部恢复入口，不能Capture→改Budget→Restore。此报告不宣称Actor迁移已经完成。

### schema2快照字段

`FState.Version=2`；保原所有字段并新增 `InitialFocus`（构造时真实初始预算）、`AccruedFocus`（末次离散变更后至当前的实际积分增加量）、`NextFocusMutationId`、`FocusHistory`。

`FFocusReceipt`存MutationId、ReceiptId、Kind、AtTime、Requested、Applied、Before、After、ReservedBefore、RegeneratedBefore。Kind为Emission/ExternalSpend/ExternalRestore；MutationId从1连续，恢复不重置。恢复率每tick不另建条目，只有实际离散扣/还留条目，积分变化纳入下一条RegeneratedBefore或末尾AccruedFocus。

Restore完整校验再替换：数值有限/范围、时序/连续游标、外部ID共域唯一、发射ID唯一且逐一绑定真实Issued、正实际数值变化、请求/实际/封顶算术、前后余额/积分链、当前总预算及reserved、两个消费来源共同确定最后真实消费。单独改Budget、抹掉消费/恢复/发射记录、凭据重放、未来/倒序、伪造量、错误版本等拒绝，活态不半替换。**Version1明确拒绝**；无旧形状暗迁移或“加Version2字段就算合法”的兼容补丁。

边界：这是内部事实的一致性校验，不是密码学防篡改。来源未把每次甲变化/所有再生上下文持久化到本纯核，因此RegeneratedBefore/AccruedFocus证明余额链声明及无离线推进，不独立证明外部上下文来源合法；真实恢复率/条件及同代世界批次仍调用者负责。账保全历史，不可随意删；合法归档及长局性能未验证，不将本轮140测试算整局存档验收。
