## 已实现的合法边界

新增 `ImportResolvedWeapon(Now,Imported,ReceiptId)`，Imported是完整`FInstance{Weapon,InstanceId,Ammo,ReservedAmmo,CooldownDeadline}`。返回`FImportResult{Accepted,Replayed}`；只有新注册有效实例可接受；校验真实模板、非零稳定ID、弹匣上限、ReservedAmmo0、有限非负绝对CD、角色存活、Now精确等于kernel.Time与独立单调receiptID。CD可以已过期，不清零。已有ID无论payload相同或不同都不能被新receipt覆盖。

导入只注册，不能免费触发Q或装备动作。保留EquippedId、共享Focus及其外部收据、在途动作、预约、PendingEvents、Issued与NextAction/Event游标。即使另一个法杖普通攻击已经预约10Focus，导入备用弩也不能清掉该预约。成功导入的原始请求与时间记录在Registration；同receipt同原请求先返回幂等结果，即使核后来已前进或武器资源已变化，也不覆盖当前实例；同receipt改参数拒绝。所有失败不占ID，纠错后可用同未成功receipt重试。

原`RegisterWeapon`保留旧零CD创建语义，并补legacy出生记录；它不用于携带已有CD的真实获取。新导入的同ID重拾应使用已有Instance与EquipCompleted，不重复导入、不重建核。具体何时、何处允许拾取与装备仍由角色/事务外层验证。

## 运行态与恢复

state schema显式升为3：Registrations对齐全部Instance并保留immutable Initial出生状态、注册时间/动作事件游标，NextImportReceiptId可核对最后成功import。WeaponRuntimeHistory只在既有真实资源变化点追加事实：技能锁点CD、实际正弹耗发射、实际装填完成；未新增战斗规则或资源算法。

Restore重放出生Ammo/CD，再逐条核对before/after、动作冻结值、真实时间、事件ID、子段、Issued弹耗对应关系，最终匹配当前全部实例。已知当前/Issued/Pending的locked技能必须有同一ActionID/InstanceID/锁点/冻结事实的SkillLock账本；这包括旧零弹耗SWD技能。原Focus、空中次数、伤害payload、reservation、动作阶段/发射游标和Pending事件校验保留。

恢复失败不改现存kernel；schema2缺新来源语义，直接拒绝等待显式迁移，没有默认填账本。内存语义校验无法证明攻击者协调伪造所有出生、动作和资源日志的可信性；D13内容摘要/同代发布及来源绑定仍属外层。历史账本不做磁盘编码/剪枝，本轮只面向首个设备获取接口。
